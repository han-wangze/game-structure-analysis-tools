# 手游市场结构分析脚本

| 脚本 | 解决什么 | 输入 → 输出 |
|---|---|---|
| `genre_analysis.py` | 按品类 / 题材 × 年份算齐结构指标（集中度 / 吸量效率 / 新品 / 存量 / 命名聚类 / Top10） | 榜单导出 csv × N → 8 张底表 Excel + 对比图 |
| `concentration_cr.py` | 按国家 × 品类 × 年份计算 CR4/CR5/CR10 与 Top10 产品名单 | 分析数据集 xlsx → 格式化 Excel 报告（收入 / 下载两维度） |
| `lifecycle_classify.py` | 给产品打「始终 / 曾经 / 从未在榜」标签，输出在榜年份记录 | 分析数据集 xlsx → 在榜产品明细 xlsx |

## 1. genre_analysis.py — 品类 / 题材结构分析（含命名聚类）

**为什么需要**：报告要判断「某个品类或题材值不值得进入」，靠的是市场结构而不是总量规模。集中度、分层增长贡献、新品渗透与变现、存量生命周期、命名同质程度这些结构指标没法用透视表一次算出来，故写成脚本按「品类 × 年份」批量算齐，输出分页签底表供报告正文取数。

**做什么**（对每个品类 × 年份各算一遍）

- **集中度**：CR3 / CR5 / CR10、头部 / 中腰部 / 尾部（40% / 70% 阈值）分层增长贡献、Top10 产品下载与收入双维度贡献；
- **吸量效率**：分层吸量效率（下载 ÷ 产品数），及增长 / 留存 / 变现三个效率维度；
- **新品表现**：新品渗透率、增长贡献、RPD 溢价；
- **存量表现**：成熟（1–3 年）/ 衰退（3 年以上）分层，产品年龄与下载增长的相关系数；
- **命名聚类**：见下。

**运行**

```
#   data/ 目录下放 Sensor Tower 导出的榜单 csv（tab 分隔、utf-16，文件名含年份）
#   需含维度列：跑品类时用 Game Sub-genre，跑题材时用 Game Theme（两种列通常同时存在）
#   Config.DIMENSION = "sub_genre"（品类）或 "game_theme"（题材）
python genre_analysis.py
```

输出：`data/game_category_analysis_report_5years.xlsx`（集中度分析 / 吸量效率分析 / 新品表现分析 / 存量产品分析 / 聚类分析汇总 / K选择评估 / 聚类成员明细 / TOP10 产品详情 8 张底表）+ CR5、吸量效率、K 选择三张对比图。字段含义见 [字段说明（fields.md）](fields.md)。

### 命名聚类：从产品名看命名范式

**背景**：头部是否趋同、还有没有细分空间，是「值不值得进」的关键。产品名是唯一能批量拿到的全量文本字段——同类产品命名往往趋同（卡牌里带 deck / tcg / roguelike，合成里带 merge / 2048）。把同一维度内的产品按名字聚成若干簇，再比较各簇的下载 / 收入 / RPD，就能看到「哪类命名范式的产品表现更好」。

**怎么做**

1. **预处理**：小写、去标点、去停用词（含 game / free 等纯噪音词）、词干提取。
2. **先降维再聚类**。这一步是整套流程里影响最大的：直接在高维稀疏 TF-IDF 上聚类时，同一维度内的产品名向量彼此都很近，簇根本分不开——实测轮廓系数只有 0.03–0.23 量级，且各簇关键词大面积重复（全维度通用词）。先做 LSA（截断 SVD）降到 20 维再聚类，同一批数据能到 0.30 量级，簇也能命名了。换停用词表、加 bigram 都只在这个数上动 0.01–0.02，量级差异只来自降维。
3. **关键词仍回到原始 TF-IDF 空间取**：降维后的簇心是线性组合、不可解释，所以取词在原始词空间做——按「簇内均值 − 全局均值」的对比度取 top 词，再跨簇去重（同一词只归对比度最高的簇）。这样既拿到好的簇结构，也保留可读的关键词。
4. **K 怎么定**——不用指标反推，见下。
5. **两个校验字段**：`top3_same_cluster_count`（收入 Top3 落在同一簇的产品数，仅 CR3≥80% 时给出）、`new_product_top_cluster_lift`（新品落入最大簇比例 ÷ 全体比例，>1 表示新品相对向该簇聚集）。

**K 为什么不能靠指标算**

在这类产品名数据上，四个常用指标互相矛盾：

| 指标 | 实际表现 | 它想告诉你 |
|---|---|---|
| 轮廓系数 | 随 K 近似单调上升（K 从 2 到 10，同一组数据 0.14 → 0.20） | 越大越好 → 永远选上限 |
| inertia（肘部法） | 每增加一档 K，SSE 只降 1%–4%，平滑得没有拐点 | 找不到肘部 |
| Calinski-Harabasz | 随 K 单调下降 | 越小越好 |
| Davies-Bouldin | 随 K 单调下降 | 越大越好（与 CH 方向相反） |

也就是说，「最优 K」在这类数据上没有数学答案；任何假装能算出来的规则（包括「取轮廓系数最大」）最后都会退化成「取搜索范围的上限」。

所以这里的做法是：**指标只用来校验，K 由业务粒度给定**。

- 粒度区间取 `K ∈ [3, 6]`——一个细分方向要在报告里讲得清楚，2 个太粗、7 个以上讲不完；
- 区间内先剔除占比 < 3% 的碎簇；
- 再取轮廓系数不低于区间峰值 90% 的**最小** K（简约原则，避免又滑向上限）；
- 每组实际用的 K 与理由写进「K选择评估」表；
- 允许用 `Config.K_OVERRIDE = {(维度值, 年份): (K, "理由")}` 逐组人工指定——**这是「业务判断」的落点**：数字能校验，不能裁决。

K 的选择依据全部落表：`K选择评估` 页签给出每个候选 K 的 inertia、SSE 降幅、轮廓系数、CH、DB、最小 / 最大簇占比、是否被选中及理由；`k_selection_curves.png` 把轮廓系数（实线）与 inertia（虚线）画在一张双轴图上，一眼就能看出「有没有拐点」。区间峰值轮廓系数低于 0.25 的组会被标 `weak-structure`，簇照出，但结论要谨慎引用。

**分出来的到底是什么：命名词族，不是玩法分类**

这是使用时最需要注意的一点。簇的分界线往往就是「名字里最突出的那个词」——一类簇的名字里都带某个通用对战词，另一类都带某个构筑词，还有一类是纯粹以某个词开头。所以每个簇都要人工过两关：

1. 这一簇的产品**是否真的属于同一玩法**？——经常不是：同一个簇里可能既有卡牌对战游戏，也有卡牌收藏类 App、卡组构筑工具类 App。
2. 如果这一簇的区分度只来自**一个通用英文词**，它测的是命名习惯，而不是细分赛道。

**局限**：它只能回答「命名层面是否趋同」，不能回答「玩法是否同质」；簇是逐年独立聚出来的、标签不跨年对齐，跨年比较时要注意；聚类结果会随特征方案版本变化，跨版本不要直接比数值。

**切换分析维度**：`Config.DIMENSION` 决定跑哪个维度——`"sub_genre"` 跑品类（读源列 `Game Sub-genre`），`"game_theme"` 跑题材（读源列 `Game Theme`）。换数据文件夹 + 改这一行即可，其余口径与输出结构完全一致；输出里的维度列名会随配置显示为 `sub_genre` 或 `game_theme`。

## 2. concentration_cr.py — CR 集中度与 Top10 底表

**为什么需要**：报告要比较 4 国 × 4 赛道 × 5 年的下载 / 收入集中度。手工透视口径容易不一致：下载 CR 与收入 CR 须各自按下载、收入排名分别取值，当年首发的判定依赖首发日期解析。

**怎么做**

- **双排名取值**：下载 CR 按下载排名、收入 CR 按收入排名分别计算，不用同一名单；
- **CR 基数按品类切换**：Open World 产品数量少，基数取 4，其余取 5；
- **当年首发标识**：兼容多种格式的首发日期，提取年份与目标年对比，表内标黄当年首发产品；
- **两套视图**：收入维度（收入 Top10）与下载维度（下载 Top10）各一张工作表，含总量行与 CR 行。

**运行**

```
#   data/analysis_dataset.xlsx ← 合并好的分析数据集
#   需含 Unified Name / Game Sub-genre / 国家 / 年份 /
#   Downloads (Absolute) / Revenue (Absolute) / Earliest Release Date 列
python concentration_cr.py
```

输出：`data/RPG手游市场分析报告.xlsx`（4 国收入维度表 + 1 张下载专项表）。

## 3. lifecycle_classify.py — 跨年榜单分类

**为什么需要**：判断哪些产品能长期留在品类 Top20、哪些只是短暂进榜，需要逐产品的在榜年份记录；人工逐年核对效率低。

**怎么做**

- **在榜标准**：当年在本品类内下载或收入任一进入 Top20 记为在榜；
- **三分类**：始终在榜（上市以来每个有数据年份都在榜）/ 曾经在榜 / 从未在榜；
- **明细输出**：保留始终 / 曾经在榜产品，附本品类逐年排名与在榜年数。

**运行**

```
#   data/analysis_dataset.xlsx ← 同上格式的分析数据集
python lifecycle_classify.py
```

输出：`data/在榜产品分析_按品类排名.xlsx`。
