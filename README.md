# 手游市场结构分析脚本

| 脚本 | 解决什么 | 输入 → 输出 |
|---|---|---|
| `genre_analysis.py` | 按**品类** × 年份算齐结构指标（集中度 / 吸量效率 / 新品 / 存量 / 命名聚类 / Top10），可改题材维度 | 榜单导出 csv × N → 6 张底表 Excel + 对比图 |
| `concentration_cr.py` | 按国家 × 品类 × 年份计算 CR4/CR5/CR10 与 Top10 产品名单 | 分析数据集 xlsx → 格式化 Excel 报告（收入 / 下载两维度） |
| `lifecycle_classify.py` | 给产品打「始终 / 曾经 / 从未在榜」标签，输出在榜年份记录 | 分析数据集 xlsx → 在榜产品明细 xlsx |

## 1. genre_analysis.py — 品类结构分析（含命名聚类）

**为什么需要**：报告要判断「某个品类值不值得进入」，靠的是市场结构而不是总量规模。集中度、分层增长贡献、新品渗透与变现、存量生命周期、命名同质程度这些结构指标没法用透视表一次算出来，故写成脚本按「品类 × 年份」批量算齐，输出分页签底表供报告正文取数。

**做什么**（对每个品类 × 年份各算一遍）

- **集中度**：CR3 / CR5 / CR10、头部 / 中腰部 / 尾部（40% / 70% 阈值）分层增长贡献、Top10 产品下载与收入双维度贡献；
- **吸量效率**：分层吸量效率（下载 ÷ 产品数），及增长 / 留存 / 变现三个效率维度；
- **新品表现**：新品渗透率、增长贡献、RPD 溢价；
- **存量表现**：成熟（1–3 年）/ 衰退（3 年以上）分层，产品年龄与下载增长的相关系数；
- **命名聚类**：见下。

**运行**

```
#   data/ 目录下放 Sensor Tower 导出的榜单 csv（tab 分隔、utf-16，文件名含年份）
python genre_analysis.py
```

输出：`data/game_category_analysis_report_5years.xlsx`（集中度分析 / 吸量效率分析 / 新品表现分析 / 存量产品分析 / 聚类分析汇总 / TOP10 产品详情 6 张底表）+ CR5、吸量效率五年对比图。字段含义见 [字段说明（fields.md）](fields.md)。

### 命名聚类：从产品名看品类结构

**背景**：头部是否趋同、还有没有细分空间，是「值不值得进」的关键。产品名是唯一能批量拿到的「玩法框架」代理信号——同类玩法的产品命名往往趋同（如卡牌里的 deck builder / tcg / roguelike）。把同一品类内的产品按名字聚成若干簇，再比较各簇的下载 / 收入 / RPD，就能看到「哪类命名框架的产品表现更好」。

**怎么做**

- 文本预处理：小写、去标点、去停用词（含 game / free 等纯噪音词）、词干提取；
- TF-IDF 向量化（特征数上限 300）；
- K-Means 聚类，K 由轮廓系数自动选取：取与峰值差距 ≤0.01 的最小 K，避免轮廓系数单调爬升带来的过度细分；
- 关键词提取：按「簇心 − 全局均值」的对比度取词，再做跨簇去重（同一词只归对比度最高的簇），保证各簇关键词互不重复；
- 两个校验字段：`top3_same_cluster_count`（收入 Top3 落在同一簇的产品数，仅 CR3≥80% 时给出）、`new_product_top_cluster_lift`（新品落入最大簇比例 ÷ 全体比例，>1 表示新品相对向该簇聚集）。

**能看出什么**（基于 2021–2025 美国 iOS 榜单数据的观察示例）

- 每个品类都有一个占下载 / 收入 70–90% 的「大盘主流命名」簇：如卡牌品类的 world / roguelike / legend，二合品类的 merge / monster / battle，即时策略的 king / squad / trench。头部收入集中在命名符合品类主流范式的产品上——命名趋同本身就是头部集中的一个信号。
- 垂直细分命名构成「高 RPD 小簇」：如卡牌里的 deck builder / tcg / roguelike 细分簇，付费深度高于大盘簇，是「命名上还有差异空间」的方向。
- 命名能区分玩法框架：deck builder、tcg / ccg、roguelike 是卡牌下不同框架，其下载 / 收入结构差异明显。

**边界**：命名聚类反映的是「命名 / 玩法框架趋同」，不能直接等同「玩法趋同」；簇是逐年独立聚出来的，簇标签不跨年对齐，跨年比较时要注意。

**改成题材维度**：脚本按品类列 `sub_genre`（源表列名 `Game Sub-genre`）做筛选与分组。改成题材分析只需两步：① 列名映射里的 `"game sub-genre"` 改为 `"game theme"`；② 把 `sub_genre` 全局替换为 `game_theme`（共 45 处：列名映射、保留列清单、四个分析模块的筛选与结果键、输出列名）。其余口径与输出结构完全一致。

## 2. concentration_cr.py — CR 集中度与 Top10 底表

**为什么需要**：报告要比较 4 国 × 4 赛道 × 5 年的下载 / 收入集中度。手工透视口径容易不一致：下载 CR 与收入 CR 须各自按下载、收入排名分别取值，当年首发的判定依赖首发日期解析。

**怎么做**

- **双排名取值**：下载 CR 按下载排名、收入 CR 按收入排名分别计算，不用同一名单；
- **CR 基数按品类切换**：Open World 产品数量少，基数取 4，其余取 5；
- **当年首发标识**：兼容多种格式的首发日期，提取年份与目标年对比，表内标黄当年首发产品；
- **两套视图**：收入维度（收入 Top10）与下载维度（下载 Top10）各一张工作表，含总量行与 CR 行。

**运行**

```
#   data/analysis_dataset.xlsx ← 合并好的分析数据集
#   需含 Unified Name / Game Sub-genre / 国家 / 年份 /
#   Downloads (Absolute) / Revenue (Absolute) / Earliest Release Date 列
python concentration_cr.py
```

输出：`data/RPG手游市场分析报告.xlsx`（4 国收入维度表 + 1 张下载专项表）。

## 3. lifecycle_classify.py — 跨年榜单分类

**为什么需要**：判断哪些产品能长期留在品类 Top20、哪些只是短暂进榜，需要逐产品的在榜年份记录；人工逐年核对效率低。

**怎么做**

- **在榜标准**：当年在本品类内下载或收入任一进入 Top20 记为在榜；
- **三分类**：始终在榜（上市以来每个有数据年份都在榜）/ 曾经在榜 / 从未在榜；
- **明细输出**：保留始终 / 曾经在榜产品，附本品类逐年排名与在榜年数。

**运行**

```
#   data/analysis_dataset.xlsx ← 同上格式的分析数据集
python lifecycle_classify.py
```

输出：`data/在榜产品分析_按品类排名.xlsx`。
