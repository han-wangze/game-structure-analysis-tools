# 数据口径与限制

README 只保留四条核心限制，这里是完整版本与实测影响。

## 1. 总量与份额只能用排序轴

榜单是「按某一个指标排序后导出的」。按收入导出的样本里，收入维度的覆盖程度高于下载维度，但覆盖是否接近全量取决于榜单深度；按下载导出的样本反之。

因此 CR5 的分母是导出样本，不默认等于整个品类市场。另一轴只能出样本内结构结论（输出表里标 `sample_only`），不能当品类级。

实测影响：Card Battler 2025 年的收入 CR5，未过滤非游戏产品时为 83.0%，过滤后为 87.0%，差的 4 个百分点全部来自非游戏产品。

## 2. 必须过滤 Category != 'Games'

下载榜样本里有 3.6% 的非游戏产品，它们同样带品类与题材标签，不滤会污染分母。

## 3. 跨年在榜用固定 Top N

不用「是否出现在导出文件里」判断在榜——各年榜单深度差异很大（实测 Block 的导出从 2021 年 1,641 行降到 2025 年 629 行），用文件出现与否会把「榜单变浅」误判成「产品掉榜」。

## 4. DAU / ARPDAU 只用于头部子样本

DAU 覆盖率按下载五分位从 8.9% 到 70% 不等，ARPDAU 覆盖率 3%–15%，都只做辅助描述，不做主指标。

## 5. 不跨数据集拼接

每个导出各自跑，结论不跨集合并；产品 ID 只在同一个数据集内跨年有效。

## 6. 不同口径的维度不并排比较

收入榜导出的品类与下载榜导出的品类分开呈现，各自内部可比。作图同理：一张图只画一个排序轴，不把两种口径的 CR 放在同一坐标轴上比高低——那样观测到的差异分不清来自口径还是来自品类。

## 7. RANK_AXIS 配错会静默出错

它决定哪个轴可以出总量结论。配错不会报错，只会让被截断的那一侧看起来像真实总量。

## 附：两处方法选择

### 细分为什么用产品模型标签，而不是产品名聚类

产品名反映的是命名习惯，不是玩法：同一玩法会因命名习惯被拆成几个簇，不同玩法会因共用词被并到一起。再加上没有买量投入、曝光量、自然量/买量拆分这些数据，名字与表现之间的差异无法与产品质量、发行商预算区分。

结果是这类簇能回答「某个命名词占多少」，回答不了「这个品类分成哪几条赛道」。细分改由平台方提供的 `Game Product Model` 标签承担，可核对，且直接对应产品形态。

### 头部留存与队列进入率的区别

- 队列进入率：按首发年份分队列，看第 k 年有多少成员进入头部 Top N。分母是**当年进榜的新品**，不是当年全部新品，结果偏乐观；上线当年（k=0）在收入轴下结构性吃亏，k=0 与 k≥1 不可直接比。
- 头部留存：在首个完整经营年进入 Top N 的新品，次年还能不能保住位置。避开了「上线当年进不了榜」的干扰，是判断头部位置是否对新进入者开放的口径。
